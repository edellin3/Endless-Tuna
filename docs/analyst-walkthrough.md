# Analyst walkthrough

1. Start with `./start.sh` and open 127.0.0.1:5173. **Demo data** is a fictional, isolated collection. Switch to **Real collection** to work with actual sources; a new installation starts empty. Check the selector before adding, reviewing or exporting.
2. Explore searches the **indexed collection**, not the live web. Type `robotics` or a quoted phrase and press Search. Multiple terms are all required; punctuation is treated safely. Use the desktop left filters or expand Filters on a narrow screen. Year, conference, organization, verified organization country, PDF and review filters combine. Browser Back/Forward and copied URLs preserve state.
3. Conference cards distinguish matching papers, collected inventory and observed official inventory. A completed ten-paper job does not mean the whole conference is indexed. Open **View matching papers**; inspect collection coverage, paper filters and match snippets. Metadata-only papers remain searchable by title/abstract; full text appears only after successful parsing.
4. Open a paper to read its abstract, ordered authors, paper-time affiliations and evidence. Follow source links or open an available local PDF. An evidence assertion carries its source, excerpt, page where available, method, time and status. Extracted values are not automatically verified. Missing nationality/residence values must not be supplied from organization location.
5. In **Add conference**, paste the conference link and click **Collect papers**. The app detects its name/year, switches to Real collection and automatically saves titles and retrieves available free PDFs. The default is ten papers; select **Entire conference** for all. There are no required preview/save/download stages. Known sources include CoRL/PMLR, WACV 2026 and the supported NeurIPS editions. Unclear sources ask for the specific missing detail.
6. Stay on the conference page: **Titles found**, **PDFs downloaded**, and **Need attention** update as work proceeds. Pause/resume or retry there. You can leave the page while the worker continues. **Collection jobs** is optional background history; technical stages and manual tools are secondary. Missing PDFs do not remove saved titles.
7. On unresolved papers, use the manual search link or supply a public candidate PDF URL. Missing optional web-search configuration is displayed. Review ambiguous candidates and distinguish proceedings PDFs from arXiv versions. Downloads reject private/local destinations and invalid PDFs. Image-only PDFs need OCR, which is not implemented.
8. Visit **Authors**, filter by organization/review or verified organization country, and open an author. Check paper-time affiliations over time. Use evidence controls to correct, confirm or reject assertions with an explicit outcome. Same-name authors remain separate. Identity confirmation requires corroboration; links can be undone without losing original paper associations. Scholar profile verification requires an actual supplied profile link and supporting evidence; lookup is not automated.
9. **Settings** shows credential presence only. Check connection explicitly discovers LAS model IDs; select an ID before **Test model**. That button sends a tiny completion. **Extract with LAS** on a paper is also an explicit model action; use local parsing/deterministic extraction without LAS. No completion runs when Settings opens. Failed LAS enrichment stores an error/retryable status and retains indexed text.
10. Choose an export scope carefully: all records in the selected collection, all papers in one conference, or all pages of the current filtered paper set. Excel has seven related sheets with stable IDs, evidence and statuses. PDF ZIPs include manifests and missing-file reports, show sizes/counts, and split to configured limits. Oversize individual PDFs are reported missing from the bundle. Download every returned part.

For a repeatable isolated browser exercise, run `npm run test:acceptance` from `frontend` after building. It uses fictional records and mocked source transport, never live LAS. See [the acceptance checklist](acceptance.md) for the precise verification scope.
