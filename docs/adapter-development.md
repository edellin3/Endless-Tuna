# Adapter development

Start with `backend/endless_tuna/adapters.py`, `collection.py` and `pipeline_store.py`. `ConferenceAdapter` is a protocol with `name`, `inventory(url, fetch) -> Inventory` and `hydrate(record, fetch) -> Metadata`. The supplied `fetch` function is the bounded public-network client; do not introduce requests/urlopen/browser scraping in an adapter or route collection traffic through LAS.

1. Inspect the official completed-edition proceedings structure and publisher documentation. Record URLs, date and supported edition/track. Inventory membership must come from an official accepted-paper/proceedings source, never a model-generated list or an arXiv search.
2. Add a narrowly scoped URL predicate and explicit adapter selection in `adapter_for`. Refuse unsupported editions, redirects away from official inventory, workshops mixed into main proceedings, and unrecognized changed markup. A zero-record parse should fail clearly, not mark an empty complete conference.
3. Return an `Inventory(records, official_count, url)`. Set `official_count` only when actually observed. Return canonical official paper pages, ordered `Person` names, abstract, identifiers, year/track and source evidence. Set `detail_pending=True` if hydration is needed. Do not fetch every PDF during inventory. Worker sampling happens after inventory; a sample does not establish completeness.
4. Hydrate each official paper independently. Prefer official linked PDF URLs and keep version `proceedings`; arXiv fallback belongs in `resolution.py`, not in membership logic. Do not merge papers by fuzzy title or authors by name. Existing canonicalization is based on official source identity; cross-host/cross-publisher identity needs explicit evidence and tests.
5. Preserve retrieval timestamps/membership via existing storage helpers and jobs. Never write unrelated tables/files or bypass lease ownership. Per-paper failures must remain isolated and retryable. Keep extraction assertions evidence-bound and separate from official inventory metadata.
6. Add small **fictional/minimal** parsing fixtures and tests for valid markup, source changes, redirects, tracks, author order, duplicate runs and incomplete inventory. Automated tests block production HTTP transports; inject fetch functions or MockTransport. Do not copy full papers into fixtures or commit PDFs.
7. Document support in collection docs/UI. Run offline tests. An optional live smoke run must be explicitly limited (normally ten papers) and reported separately; full-conference download is an analyst action.

`NeurIPS2024` supports main proceedings for 2024. `neurips2026.py` reads the official virtual-program feeds; its `multi_track` flag permits record-specific official tracks rather than forcing everything into the job track. Completeness counts distinct canonical papers, not oral/poster presentation duplicates. Repeated source-access denials preserve inventory and completed files in a partial job. `MetadataAdapter` supports explicit citation metadata and JSON manifests; `CSVAdapter` supports the [CSV inventory contract](collection.md). JSON provider search is pluggable via `SearchProvider`/`JSONSearchProvider` in `resolution.py`; results need title/author evidence and general-search candidates require review. Do not scrape search result pages or silently install a provider.

LAS is not needed to implement an inventory adapter. If bounded language extraction becomes necessary, use only `las.py`, validated schemas and untrusted-data prompts; retain source excerpts and failure status. New adapters must not assume tools, native web search or structured-output gateway extensions.
