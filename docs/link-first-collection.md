# Manual staged collection (advanced)

The normal Add conference page now uses [automatic collection](automatic-collection.md). This document describes the optional staged flow at `#/add/manual`, retained for source inspection and advanced use. It switches to Real collection automatically; sample research remains in Demo. The prior custom-format form is available through **Advanced import** at `#/add/advanced`.

1. Paste or drop a public conference, accepted-paper or proceedings URL. Markdown-wrapped links are also accepted. **Preview paper list** reads the source, detects supported formats, infers the event name/year where supplied, and previews up to eight titles. No papers or PDFs are added by preview.
2. Review/correct the name and event year. Choose the first ten titles for a test, or explicitly select all titles. **Save paper titles** creates an inventory-only durable job and opens the conference page. This job uses the preview's persisted snapshot; it never hydrates paper pages, searches repositories or downloads PDFs. A title-only job can complete while PDF coverage is zero.
3. Review the titles on the conference page. **Find free PDFs · next 10** creates a separate PDF job for missing files only. Check **Process all remaining papers** for a full request. Existing PDFs and paper identities are preserved; a PDF sample does not reset a previously complete inventory. Job progress, cancellation, review links and the next action stay on the conference page; jobs also link directly back to it.

The exact reported URL, `https://proceedings.mlr.press/v270/`, detects Conference on Robot Learning and event year **2024**, rather than the volume publication year 2025. You no longer need to pick an adapter, enter the conference metadata beforehand, or manually switch out of Demo. Re-adding a matching source/year opens the existing edition instead of creating another job.

## Source handling and honest limits

Any public URL can be submitted, but readable HTML is not universal. Supported PMLR/RSS/NeurIPS inventories retain their specialized parsing and completeness rules. Unknown pages use a conservative linked-paper-list reader: explicit paper containers with titles and linked paper pages/PDFs. It does not turn navigation links into papers, infer membership from search results or follow arbitrary web instructions. Generic completeness remains unknown. Paper-page citation tags can later supply ordered authors; authors are not invented during title-only collection.

If the page is a homepage rather than a listing, intake offers up to eight explicitly linked accepted-paper/proceedings sources. CoRL year-specific homepages can additionally suggest a matching entry from the actual public PMLR directory, which must be inspected before it becomes a paper inventory. JavaScript-only, sign-in, inaccessible or unrecognized pages show an actionable error with links to discovery and custom/CSV import. No browser automation, access-control bypass, automatic adapter generation or universal conference crawler is claimed.

Preview snapshots live in each collection's SQLite `intake_previews` table for 24 hours and are isolated between collections. The normal UI requests Real explicitly. Saving is allowed only in Real. Expired previews require rechecking; source-derived event-year conflicts fail before collection. Migration 009 adds previews and a job `kind` column; existing jobs keep `collect` behavior and runtime records are preserved.

## Free-PDF lookup

The separate PDF job tries the paper's official PDF first, then conservative arXiv matching, then public OpenAlex open-access location metadata. OpenAlex can point to publisher, institutional repository, subject repository or preprint copies with direct `pdf_url` links. Only locations explicitly marked `is_oa: true` enter the lookup. It uses the public no-key API, at most five works per query, at most 100 locations/work and 30 distinct candidates, a 2 MB response limit, existing public-IP-pinned traffic controls and a 24-hour per-title SQLite cache. No key/account is created and no paid content API is used. Provider rate limits/access failures stay visible.

[OpenAlex API reference](https://help.openalex.org/api/), [search](https://help.openalex.org/api/searching/), and [location fields](https://help.openalex.org/data/locations/) were inspected for this implementation. Every automatic alternate-copy match requires an exact normalized title and complete normalized author-name evidence. Multiple work identities and partial/mismatched authors go to Review queue; author identity is never merged by name. Multiple locations of one evidence-matched OpenAlex work are attempted in bounded sequence (up to four transfers total per paper). Versions are labeled with their OpenAlex work ID and reported manuscript version. The original conference membership remains tied to its listing, never inferred from an alternate copy.

If the paper metadata page is inaccessible, the saved title can still be searched; absent author evidence prevents automatic alternate-copy acceptance. Failed/blocked/invalid PDFs do not erase titles or stop other papers. Confirmed/manual candidates, the optional configured JSON search gateway, and manual PDF-URL review remain available. PDF bytes must validate and parse before availability is recorded; image-only results remain visibly OCR-required. Provenance, URLs, timestamps, hashes, byte sizes and versioned page text use the existing download model.

This searches multiple open sources, not every page on the internet. Landing-page-only locations, obscure author sites absent from the index and inaccessible files may remain unresolved. No complete PDF-coverage guarantee is made. LAS is not used anywhere in this workflow.
