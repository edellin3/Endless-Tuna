# WACV 2026 collection

Paste `https://wacv.thecvf.com/Conferences/2026` in **Add conference**, then click **Collect papers**. Titles and free PDFs are collected automatically on one conference page. The default is ten papers; choose Entire conference for all. The collector follows the official Conference Site → Papers links; direct virtual-index/Papers URLs also work. See [automatic collection](automatic-collection.md). Optional manual title-only jobs remain available in advanced tools.

The advanced form also recognizes these URLs with Auto or **WACV 2026 official paper list**; it requires Real collection and year 2026. The source is normalized to the official Papers listing so homepage/listing inputs open the same edition. Discovery includes WACV under **CVF / WACV** and supports its inventory-access check.

## Official source structure

Inspected live 2026-11-12:

- Homepage → virtual index → Papers page, all on `wacv.thecvf.com`, bounded to three pages. Changed links/foreign redirects fail explicitly.
- The Papers page's inline `start(...)` call references `/static/virtual/data/wacv-2026-orals-posters.json`. The collector reads this exact public feed; it does not execute JavaScript or follow profile APIs.
- The inspected feed contains **916 presentation entries: 831 posters and 85 orals**. Its static `noscript` paper list contains the same 831 poster IDs. Each oral supplies a relationship to a poster entry. Only the distinct poster-paper identities are collected; oral presentation relationships are retained as identifiers. Titles never establish identity or deduplication.
- Feed count/pagination, positive IDs, unique poster/source IDs, accepted decisions, main-conference source group, oral relationships, and exact static-list/feed membership agreement are validated before a complete inventory claim. Workshops and other years are outside this collector. Stable numeric poster ID order makes sampled jobs reproducible.
- Ordered author names and inline abstracts are retained. Profile institutions are deliberately ignored as paper-time affiliation evidence. Missing name slots remain visibly missing and need review.
- The separate abstracts URL referenced by the page currently returns 404; abstracts already exist in the main feed and no request to that unnecessary endpoint is made.

The published main-paper listing is the inventory scope. It does not imply complete proceedings/PDF coverage or coverage of separate workshop sites. Counts can change with official updates; they are not hard-coded in the collector.

## Papers versus presentation materials

The inspected feed supplies no explicit `paper_pdf_url` values. Its generic `url` field contains project/code sites, and `eventmedia` contains slides, poster images and videos. These are never relabeled or downloaded as paper PDFs. In particular, a slides PDF is not an accepted-paper PDF.

The separate PDF job uses the existing conservative arXiv and OpenAlex OA-copy search, plus configured/manual candidates where available. Exact normalized title and complete author evidence are required for automatic alternate-copy acceptance; ambiguous copies go to Review queue. Versions, original/final URLs, timestamps, content hashes and extracted pages retain provenance. Public-source access controls are preserved. No LAS call is needed.

## Verification

Offline WACV fixtures use clearly fictional titles/authors and mocked transports. They cover all supported entry points, same-title distinct papers, author order and identity separation, ignored profile affiliations/media, oral relationships, count/pagination/membership mismatch, invalid IDs/URLs, unsupported tracks/years, preview, advanced form and separate title/PDF jobs. Browser acceptance includes the exact homepage input with a fictional snapshot, then actual backend/worker title and PDF stages through the real Vite proxy. These are not live-source checks.

Separate live smoke: the exact homepage yielded **831 titles**. Two titles were saved in temporary isolated Real storage with **zero PDFs**. A subsequent explicit one-paper PDF job downloaded and indexed **one PDF**, with no failures. Both stages retained an incomplete full-inventory flag because only two titles were stored. Temporary databases/PDFs were removed; an ignored summary remains at `var/wacv-live-smoke.json`. Existing real/demo collections were untouched, and no LAS request occurred. This does not verify all 831 PDFs.
